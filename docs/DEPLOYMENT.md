# Deployment: private beta on Cloudflare Pages (no cost)

**Status:** prepared, **not deployed**. Nothing in this repository deploys by itself. Deploy only with the owner's explicit authorisation.

The site is static: `npm run build` writes `dist/`. There is no server, database, account system, API key or payment. Everything in `dist/` is public by nature; there are no secrets to protect, and the build is checked for accidental ones.

## What the build produces for Cloudflare Pages

| File in `dist/` | Purpose |
| --- | --- |
| `index.html`, `assets/*` | The app. Asset names carry a content hash. |
| `_headers` | Generated by `scripts/release.mjs`: Content-Security-Policy, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, `X-Frame-Options: DENY`, `Cross-Origin-Opener-Policy`; on beta builds `X-Robots-Tag: noindex, nofollow`; one-year immutable caching for `/assets/*`. |
| `robots.txt` | Beta: `Disallow: /`. Production: `Allow: /`. |
| no `404.html`, no `_redirects` | Deliberate. Without a top-level `404.html`, Pages treats the project as a single-page app and serves `index.html` for every path that is not a file, so `/campaigns/fall-of-rome/ending` works when opened directly or refreshed. A `/* /index.html 200` rule is unnecessary. `scripts/check-dist.mjs` fails the build check if either file appears. |

Saved games live in the visitor's browser (`localStorage`, keys `tat.save.rome-alternate` and `tat.settings`). They belong to the site's origin, so they keep working across deployments to the same address. A visitor who opens a different address (a preview URL, or a custom domain added later) starts with empty storage there.

## Build settings

| Setting | Value |
| --- | --- |
| Framework preset | None (or Vite) |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Root directory | (leave empty) |
| Environment variable `NODE_VERSION` | `22` |
| Environment variable `VITE_RELEASE_CHANNEL` | `beta` (default if unset). Use `production` only at public launch. |
| Environment variable `VITE_ANALYTICS_ENDPOINT` | Optional. `https://<code>.goatcounter.com/count`. Leave unset to send nothing. See [Analytics](#analytics-optional). |
| Environment variable `VITE_FEEDBACK_URL` | Optional. The `https://` link to the beta questionnaire ([BETA_FEEDBACK.md](BETA_FEEDBACK.md)). The feedback links are hidden when unset. |

These values are public (they end up in the JavaScript). Do not put anything secret in a `VITE_` variable. An invalid value stops the build with a clear message rather than producing a half-configured site.

Cloudflare's free plan limits that matter here (checked October 2026; check again before deploying, they change): 500 builds a month, 1 concurrent build, 20-minute build timeout, 20,000 files, 25 MiB per file. This site is about a dozen files and well under 1 MB.

## Step by step

0. **Make the GitHub repository private** if it is not already: GitHub → the repository → **Settings → General → Danger Zone → Change visibility → Make private**. Private repositories get GitHub's free Actions allowance (2,000 minutes a month on the Free plan); with no spending limit set, GitHub stops jobs at the limit rather than charging.
1. **Create or sign in to a Cloudflare account** with the owner's email. The free plan is enough. If Cloudflare asks for payment details for Pages, stop: nothing in this project needs them.
2. In the dashboard open **Workers & Pages → Create → Pages → Connect to Git** (Cloudflare renames menus from time to time; look for creating a *Pages* project from a Git repository, not a Worker).
3. Authorise the Cloudflare GitHub app for the repository `nesasone991/the-alternate-timeline` only (not all repositories).
4. Choose a project name. It becomes the address `https://<project-name>.pages.dev`; it is visible to testers, so pick something neutral (for example `alternate-timeline-beta`).
5. Production branch: `main`. Enter the build settings above, including `NODE_VERSION=22` and `VITE_RELEASE_CHANNEL=beta`. Add `VITE_FEEDBACK_URL` once the questionnaire exists; add `VITE_ANALYTICS_ENDPOINT` only if analytics are wanted.
6. **Save and Deploy.** The first build takes a few minutes. Every later push to `main` redeploys automatically; pushes to other branches create preview deployments at their own addresses, which Cloudflare already marks `noindex`.
7. In the project settings leave **Web Analytics** off (it would inject a third-party beacon that the Content-Security-Policy blocks) and do **not** add a custom domain without the owner's approval.
8. Run the [checks on the live site](#checks-on-the-live-site). Then share the `pages.dev` address privately with testers.

To take the beta offline: **Settings → Delete project** (or remove the deployment). Rolling back to an earlier build: **Deployments → … → Rollback**.

### Changing settings later

Environment variables are read at build time. After changing one, start a new deployment (**Deployments → Retry deployment**, or push a commit). Bump `APP_VERSION` in `src/config/release.ts` and `version` in `package.json` for each beta release so testers can quote the build shown in the footer (the short commit id is added automatically from Cloudflare's `CF_PAGES_COMMIT_SHA`).

## Checks on the live site

Automated checks cover the build and an emulation of Pages (`wrangler pages dev`) in CI, but not the real host. On the deployed `pages.dev` address:

- [ ] Open each of these in a new private window, then press reload: `/`, `/explore`, `/how-it-works`, `/about`, `/privacy`, `/campaigns/fall-of-rome`, `/campaigns/fall-of-rome/workspace`, `/campaigns/fall-of-rome/workspace?mode=alternate`, `/campaigns/fall-of-rome/ending`, `/no-such-page` (shows the app's "Page not found"). No browser error page appears.
- [ ] Make two decisions, reload, and see "Your progress was restored". Close the tab, reopen the address, and the campaign is still there.
- [ ] The "Private beta" bar is on every page; the footer shows `Private beta 0.9.0-beta.1, build <commit>`.
- [ ] Response headers of `/campaigns/fall-of-rome/ending` (browser developer tools → Network → the document request) include `content-security-policy`, `x-robots-tag: noindex, nofollow` and `x-frame-options: DENY`; `/robots.txt` says `Disallow: /`.
- [ ] The browser console shows no Content-Security-Policy errors on the home page, the workspace and the ending page.
- [ ] On a phone (iOS Safari and Android Chrome if possible): play a campaign to the end, open the ending page, rotate the phone.
- [ ] If analytics are on: play to an ending and see the events appear in the GoatCounter dashboard within a few minutes (with Do Not Track off).
- [ ] If the feedback link is set: it opens the questionnaire in a new tab.
- [ ] Deploy a trivial change, keep an old tab open, then click to the ending page in the old tab: it either works or shows "A new version is available" with a reload button.

Automated run against the live site, from GitHub Actions (no local setup): **Actions → Verify live site → Run workflow**, enter the address (for example `https://alternate-timeline-beta.pages.dev`), or from a terminal `gh workflow run verify-live.yml -f url=https://<project-name>.pages.dev`. It prints the response headers and `robots.txt`, then runs `tests/e2e/deployment.spec.ts` on desktop and mobile: every route opened directly and reloaded, saves across reloads, a full campaign to the ending page, beta labels, `noindex`, security headers, console errors and requests to other hosts.

The same tests from your own computer (repository and Chromium installed):

```bash
E2E_BASE_URL=https://<project-name>.pages.dev E2E_CLOUDFLARE=1 npx playwright test deployment
```

The deployment tests only read pages and use the browser's own storage; they do not change anything on the server.

## Analytics (optional)

Off unless `VITE_ANALYTICS_ENDPOINT` is set. What is measured and why: [ARCHITECTURE.md → Usage counts](ARCHITECTURE.md#usage-counts-analytics). Setup:

1. Create a free GoatCounter account at goatcounter.com and a site code (for example `tat-beta`). GoatCounter's hosted service says it is free for reasonable use, including small businesses; check its current terms first.
2. Set `VITE_ANALYTICS_ENDPOINT=https://tat-beta.goatcounter.com/count` in the Pages project and redeploy. The build adds that one origin to `connect-src` in the Content-Security-Policy; nothing else is loaded from GoatCounter (no script).
3. Do not enable GoatCounter's optional "individual pageviews" collection; aggregate counts are enough.
4. Events appear in GoatCounter as paths named `campaign-start`, `decision-1-complete`, `decision-3-complete`, `campaign-complete`, `ending-imperial-survival`, `ending-fragmented-survival`, `ending-imperial-collapse`, `replay-start`, `new-timeline-from-ending`, `new-timeline-from-workspace`.

Reading the numbers: completion rate = `campaign-complete` ÷ `campaign-start`; drop-off = `decision-1-complete` and `decision-3-complete` against starts; ending distribution = the three `ending-*` counts; replay usage = `replay-start` ÷ `campaign-complete`; new timelines = the two `new-timeline-*` counts. Counts are approximate: visitors with Do Not Track, Global Privacy Control, the Settings toggle off or blocking extensions are not counted.

## Local production check

```bash
npm ci
npm run build             # typecheck + build (beta by default)
npm run check:dist        # Pages routing rules, headers, robots, secrets, size budget
npm run preview           # http://localhost:4173 (Vite's preview does not apply _headers)
npx --yes wrangler@4.151.1 pages dev dist --port 8788   # Cloudflare's Pages emulator, applies _headers
```

`wrangler pages dev` runs locally and needs no Cloudflare login. Run the deployment tests against it with `E2E_BASE_URL=http://localhost:8788 E2E_CLOUDFLARE=1 npx playwright test deployment`.

## GitHub Pages (alternative, not prepared)

GitHub Pages ignores `_headers` (no security headers, no `noindex` header). It would need `dist/404.html` as a copy of `index.html` for deep links, and `base: '/<repo>/'` in `vite.config.ts` for a project page. The build check would then have to allow `404.html`. Cloudflare Pages is the prepared host.
